## Mol Voice Assistant – сервер распознавания речи и парсинга команд

Этот проект – backend‑сервис на `Flask`, который:

- **принимает аудиофайл** (POST `/recognition/text`);
- **распознаёт речь** с помощью моделей **Whisper** (через `faster-whisper`) и/или **Vosk**;
- **парсит распознанный текст** локальной LLM‑моделью (`llama-cpp-python`) по заданному системному промпту;
- возвращает **распознанный текст и структурированный набор команд** в формате JSON.

Проект рассчитан на локальный запуск и интеграцию с настольным или мобильным голосовым ассистентом.

---

## Стек технологий

- **Язык**: Python 3.10+  
- **Web‑фреймворк**: `Flask`, `flask-cors`  
- **Распознавание речи**:
  - `faster-whisper` (основной путь, high‑quality Whisper),
  - `vosk` + `pydub` (альтернативный путь).
- **LLM / парсинг команд**: `llama-cpp-python` (локальная LLaMA‑совместимая модель)  
- **Конфигурация**: `python-dotenv`, `.env`  

Список зависимостей см. в `requirements.txt`.

---

## Структура проекта

- `main.py` – точка входа, инициализация `Flask` и регистрацию blueprints.
- `app/config.py` – загрузка переменных окружения, пути к моделям и настройкам.
- `app/routes/recognition.py` – HTTP‑роуты, основная логика обработки запроса `/recognition/text`.
- `app/services/audio_recognition.py` – функции распознавания речи:
  - `recognize_audio()` – через Vosk;
  - `recognize_audio_by_whisper()` – через Whisper (`faster-whisper`).
- `app/services/llm_command_parser.py` – функция `parse_text()`, вызывающая LLM‑модель для разбора текста в команды.
- `.env.example` – пример конфигурации окружения.

## Требования

- **Python**: 3.10 или новее.
- **Системные зависимости**:
  - FFmpeg (для `pydub` и работы с различными форматами аудио – `wav`, `mp3`, `ogg` и т.д.);
  - при использовании GPU‑ускорения для Whisper – корректно установленный CUDA‑стек (опционально).
- **Модели**:
  - модель Vosk для русского языка (или нужного языка);
  - модель Whisper (`small`, `medium` и т.п.) для `faster-whisper`;
  - локальная LLaMA‑совместимая модель для `llama-cpp-python`.

## Установка

1. **Клонировать репозиторий** (или скопировать проект в нужную директорию).

2. **Создать и активировать виртуальное окружение** (рекомендуется):

```bash
python -m venv venv
source venv/bin/activate  # на macOS / Linux
# venv\Scripts\activate   # на Windows (PowerShell/cmd)
```

3. **Установить зависимости**:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

> **Важно:** для `llama-cpp-python` и `faster-whisper` может потребоваться дополнительная системная настройка (компилятор, BLAS, CUDA и т.д.), в зависимости от вашей платформы.

4. **Установить FFmpeg** (если ещё не установлен). На macOS:

```bash
brew install ffmpeg
```

На других системах – согласно вашей ОС.

## Настройка переменных окружения

Создайте файл `.env` в корне проекта (рядом с `main.py`) по образцу `.env.example` и заполните значения:

```env
VOSK_MODEL_PATH="/absolute/or/relative/path/to/vosk-model"
UPLOAD_FOLDER="uploads"
FRAME_CHUNK=16000
SYSTEM_PROMPT='Твой системный промпт для LLM'
LLM_MODEL_PATH="/absolute/or/relative/path/to/llm-model.gguf"
HF_AUTH_TOKEN="your_huggingface_token_if_needed"
```

Пояснения:

- **`VOSK_MODEL_PATH`** – путь к директории с моделью Vosk (например, скачанной с сайта разработчиков).  
- **`LLM_MODEL_PATH`** – путь к файлу модели LLaMA‑совместимой (формат `gguf` и т.п.), которую использует `llama-cpp-python`.  
- **`UPLOAD_FOLDER`** – папка, куда временно сохраняются загружаемые аудиофайлы. Относительный путь рассчитывается от корня проекта.  
- **`FRAME_CHUNK`** – размер аудиофрейма для Vosk (по умолчанию 16000).  
- **`SYSTEM_PROMPT`** – системный промпт, который определяет, как LLM должна интерпретировать текст пользователя и какие команды возвращать. Здесь вы можете описать формат ответа (JSON, список команд и т.п.).  
- **`HF_AUTH_TOKEN`** – токен Hugging Face (если вы используете приватные или требующие авторизации модели Whisper для `faster-whisper`).  

Переменные дополнительно обрабатываются в `app/config.py`, где формируются абсолютные пути относительно корня проекта.

## Запуск приложения

Находясь в корне проекта (где лежит `main.py`), запустите:

```bash
python main.py
```

По умолчанию Flask‑сервер стартует на `http://127.0.0.1:5000` (порт можно изменить через переменные окружения или запуск через WSGI‑сервер при продакшен‑развёртывании).

## HTTP API

### POST `/recognition/text`

Маршрут определён в `app/routes/recognition.py` и ожидает **форму с файлом**:

- **Поле формы**: `audio`  
- **Тип**: `multipart/form-data`

**Пример запроса с помощью `curl`:**

```bash
curl -X POST "http://127.0.0.1:5000/recognition/text" \
  -H "Content-Type: multipart/form-data" \
  -F "audio=@/полный/путь/к/файлу.wav"
```

**Успешный ответ (пример):**

```json
{
  "message": "Файл command.wav успешно загружен",
  "recognized_text": "включи свет в спальне",
  "commands": "{ ...результат работы LLM, зависит от SYSTEM_PROMPT... }"
}
```

Где:

- **`recognized_text`** – текст, распознанный моделью Whisper (функция `recognize_audio_by_whisper`).  
- **`commands`** – строка с результатом парсинга текста моделью LLM (`parse_text`), формат зависит от вашего системного промпта (рекомендуется возвращать JSON или чётко структурированный текст).

**Возможные ошибки:**

- `400 {"error": "Файл не найден"}` – поле `audio` отсутствует в запросе.
- `400 {"error": "Имя файла пустое"}` – файл не выбран.
- `500 {"error": "Ошибка обработки аудио ..."}` – ошибка при распознавании.
- `500 {"error": "..."}` – любая другая ошибка в процессе вызова Whisper или LLM.

## Как это работает внутри

1. **Получение файла**  
   Роут `/recognition/text` принимает файл, проверяет наличие и имя, сохраняет его во временную директорию `UPLOAD_FOLDER`.

2. **Распознавание речи**  
   Сейчас для преобразования аудио в текст используется:
   - `recognize_audio_by_whisper(filepath)` из `app/services/audio_recognition.py`, построенный на `faster-whisper`.
   - (Опционально можно использовать `recognize_audio()` на Vosk – код уже есть.)

3. **Парсинг команд**  
   Полученный текст передаётся в `parse_text(text)` из `app/services/llm_command_parser.py`, которая:
   - инициализирует LLM через `llama_cpp.Llama` с моделью `LLM_MODEL_PATH`;
   - формирует промпт на основе `SYSTEM_PROMPT` и текста пользователя;
   - получает и возвращает текстовый ответ (обычно ожидается JSON/команды).

4. **Формирование ответа**  
   В `recognition.py` собирается JSON с информацией об успехе, распознанным текстом и результатом LLM.

## Рекомендации по настройке моделей

- **Whisper / `faster-whisper`**:
  - В `app/config.py` задаются:
    - `DEVICE` – `"cpu"` или `"cuda"`;
    - `WHISPER_MODEL_SIZE` – `"small"`, `"medium"` и т.п.
  - В `audio_recognition.py` уже настроено:
    - `compute_type="float16"` для GPU (`cuda`);
    - `compute_type="int8"` для экономии памяти на CPU.

- **Vosk**:
  - Убедитесь, что `VOSK_MODEL_PATH` указывает на распакованную директорию модели Vosk.
  - Функция `recognize_audio()` приводит аудио к частоте дискретизации `FRAME_RATE` и моно‑каналу.

- **LLM‑модель (`llama-cpp-python`)**:
  - Выберите модель подходящего размера и формата (обычно `gguf`).
  - Путь к модели укажите в `LLM_MODEL_PATH` в `.env`.
  - Скорректируйте `SYSTEM_PROMPT`, чтобы LLM возвращала команды в нужном формате.
