## Mol Voice Assistant — сервис распознавания речи и разбора голосовых команд

Backend на `Flask` для голосового управления ЛИМС. Принимает аудио, распознаёт речь
и превращает её в структурированную команду:

- **приём аудио** — POST `/recognition/text`, поля `audio` и `context`;
- **распознавание речи** — `faster-whisper`, модель `small`, русский, VAD-фильтр;
- **разбор текста в команду** — облачная LLM на **Groq** (`llama-3.3-70b-versatile`);
- **ответ** — JSON с распознанным текстом и командой (`nav` / `form` / `api` / `none`).

Исполняет команду фронт ЛИМС: сервис только называет команду, сверку с реестром роутов
и вызов делает клиент.

> **Текст команд уходит в облако Groq.** Локально работает только распознавание речи.

---

## Стек

- **Python** 3.10+
- **Web** — `Flask`, `flask-cors`
- **Речь** — `faster-whisper` (CTranslate2, модель качается с Hugging Face при первом старте)
- **LLM** — `groq` SDK, модель задаётся в `app/services/llm_command_parser.py`
- **Конфигурация** — `python-dotenv` + `.env`, системный промпт — отдельный файл

## Структура проекта

```
main.py                              точка входа: sys.path на app/, логирование, Flask
prompts/system.md                    системный промпт (не в git, см. «Установка»)
app/config.py                        переменные окружения, чтение промпта
app/routes/recognition.py            роут POST /recognition/text
app/services/audio_recognition.py    recognize_audio_by_whisper()
app/services/llm_command_parser.py   parse_text(): сборка промпта, вызов Groq, разбор JSON
app/services/prompt_builder.py       ретривер: выбирает часть реестра под сказанную фразу
utils/tokens.py                      счётчик токенов промпта по секциям
received_voices/                     сохранённое аудио и расшифровки
voice.log                            лог: аудио, расшифровка, промпт, токены, ответ модели
```

## Требования

- **Python** 3.10 или новее.
- **Ключ Groq** — `GROQ_API_KEY`. Без него разбор команд не работает.
- **Интернет** — для вызова Groq на каждой команде.
- **`prompts/system.md`** — промпт с реестром команд. Файл в `.gitignore`, в клоне его нет.
- Модель Whisper скачивается автоматически при первом запуске (~500 МБ для `small`)
  и кэшируется в `~/.cache/huggingface`.

FFmpeg больше не нужен: `faster-whisper` читает контейнеры сам, `pydub` из тракта убран.

## Установка

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

Затем положить системный промпт в `prompts/system.md`. Файл не хранится в репозитории. Без него
`app/config.py` падает на импорте с `FileNotFoundError`.

### Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```env
GROQ_API_KEY="gsk_..."      # ключ Groq, обязателен
UPLOAD_FOLDER="received_voices"  # куда складывать аудио и расшифровки
HF_AUTH_TOKEN=""            # токен Hugging Face, нужен только для приватных моделей Whisper
```

`VOSK_MODEL_PATH`, `LLM_MODEL_PATH` и `FRAME_CHUNK` остались в `.env.example`
от прежней локальной схемы и сейчас ни на что не влияют.

Устройство и размер модели Whisper задаются в `app/config.py`:

```python
DEVICE = "cpu"               # "cuda" при наличии GPU
WHISPER_MODEL_SIZE = "small" # или "medium"
```

`compute_type` выбирается по устройству автоматически: `int8` на CPU, `float16` на CUDA.

## Запуск

```bash
python main.py
```

Сервер поднимается на `http://127.0.0.1:5000`.

Если запуск падает на `from config import ...`, значит интерпретатор не видит `app/`
как корень пакетов:

```bash
PYTHONPATH=app ./venv/bin/python main.py
```

> **На macOS порт 5000 занимает ControlCenter** (AirPlay Receiver). Flask стартует рядом,
> но для проверок через `curl` удобнее поднять сервис на другом порту.

## HTTP API

### POST `/recognition/text`

`multipart/form-data`:

| Поле | Обязательно | Что это |
|---|---|---|
| `audio` | да | аудиофайл: `.webm`, `.wav`, `.mp4`, `.m4a`, `.ogg`, `.mp3` |
| `context` | нет | состояние страницы клиента, например `route=order.edit` |

`context` сужает выдачу ретривера: маршрут из него отсекает команды, неприменимые
на текущей странице.

Имя сохраняемого файла генерируется сервисом по времени, расширение берётся
из белого списка — имя от клиента в файловую систему не попадает.

**Запрос:**

```bash
curl -X POST "http://127.0.0.1:5000/recognition/text" \
  -F "audio=@/путь/к/файлу.webm" \
  -F "context=route=order.edit"
```

**Ответ 200:**

```json
{
  "message": "Файл command.webm успешно загружен",
  "recognized_text": "Запиши количество образцов 5",
  "commands": {
    "kind": "form",
    "name": "form.set",
    "args": {
      "field": "requests[].details.amount_sample",
      "value": "5"
    }
  }
}
```

`commands.kind` — всегда одно из `nav`, `form`, `api`, `none`. Если модель вернула
не-JSON или незнакомый `kind`, приходит `{"kind": "none", "raw": "<ответ модели>"}`:
клиент в этом случае ничего не исполняет. `name` — строка из реестра, `args` — её параметры;

**Ошибки:**

| Код | Тело | Когда |
|---|---|---|
| 400 | `{"error": "Файл не найден"}` | нет поля `audio` |
| 400 | `{"error": "Имя файла пустое"}` | файл не выбран |
| 500 | `{"error": "Ошибка обработки аудио через Whisper: ..."}` | падение распознавания |
| 500 | `{"error": "..."}` | падение разбора команды, обычно ошибка Groq |

## Как это работает внутри

1. **Приём.** Роут проверяет поле `audio`, генерирует имя по времени, сверяет расширение
   с белым списком и сохраняет файл в `UPLOAD_FOLDER`.
2. **Распознавание.** `recognize_audio_by_whisper()` прогоняет файл через `faster-whisper`
   с `language="ru"` и VAD-фильтром, который срезает тишину и шум до транскрипции.
   Расшифровка ложится `.txt` рядом с аудио и пишется в `voice.log`.
3. **Сборка промпта.** `prompt_builder.build()` не отдаёт модели весь реестр: из 128 строк
   к одной команде относятся единицы. Близкие строки ищутся косинусом по символьным
   триграммам, в промпт идут top-8 плюс постоянный каркас (формат ответа, правила, контекст).
   **~3800 → ~1100 токенов.** Триграммы, а не слова, потому что Whisper теряет буквы:
   «коверческое предложение», «ОО» вместо «ООО».
4. **Разбор.** `parse_text()` шлёт промпт в Groq с `temperature=0`, снимает markdown-обёртку
   с ответа, парсит JSON и проверяет конверт. Расход токенов из `usage` пишется в лог.
5. **Ответ.** Роут собирает JSON с расшифровкой и командой. Сверку `name` с реестром роутов
   делает фронт — реестр живёт там же, где `router.visit()`.

## Разработка и отладка

**Лог.** `voice.log` в корне: имя аудиофайла, расшифровка, собранный промпт, что нашёл
ретривер, расход токенов (вход/выход/всего) и ответ модели. Дублируется в stdout.

**Проверка ретривера** — прогон по реальным расшифровкам, без обращений к Groq:

```bash
PYTHONPATH=app ./venv/bin/python app/services/prompt_builder.py --check
```

Печатает recall и размер промпта. Падает, если ретривер потерял хоть одну команду
из корпуса. Запускайте после каждой правки `prompts/system.md`.

Посмотреть, что уходит в модель на конкретной фразе:

```bash
PYTHONPATH=app ./venv/bin/python app/services/prompt_builder.py "сформируй коммерческое предложение"
```

**Стоимость промпта** — разбивка по секциям, чтобы видеть, что резать:

```bash
./venv/bin/python utils/tokens.py
```

**Смена модели** — две строки в `app/services/llm_command_parser.py`: `model=` и `stop=`.
Рядом закомментирована ветка `openai/gpt-oss-120b`, ей нужен разрез ответа по `<END>` вручную.

**Промпт читается один раз на импорте `config`** — после правки `prompts/system.md`
перезапустите Flask.

## Известные ограничения

- У клиента Groq не выставлен `max_retries`: SDK молча повторяет запрос со сном 30 с,
  клиент в это время висит без таймаута.
- Маршрут из `context` отсекает только поля формы; api-команды показываются на любой странице.
